# 贡献指南

## 重要声明：本项目不接受外部 PR

muslext 可能会被大量用户集成到自己的发行版、制品、SDK 或商业产品中。为了让每一个下游用户都能放心使用，本项目的版权来源必须保持绝对干净，不能给用户引入任何合规风险。

因此，本项目采用与 SQLite 类似的运作模式：

- 不接受任何外部 Pull Request；
- 外部提交的 PR 会被直接关闭，不进入 review；
- 所有代码修改由维护者完成；
- 发现问题、需要新接口或改进建议，请提交 issue，由维护者评估和实现。

这不是对贡献者的不尊重，而是为了确保：

1. 每一行代码都能追溯到维护者的净室实现；
2. 不引入来源不明、许可证不明或与 0BSD 不兼容的代码；
3. 下游用户可以无条件信任本项目的版权状态。

请不要在 issue 中粘贴大段第三方实现代码。描述行为和需求即可，维护者会用净室方式实现。

## 可以提交什么

欢迎提交 issue，包括：

- 构建失败、运行时错误、ABI/行为不兼容；
- 需要补充的 glibc/musl 接口；
- 某个项目或软件包无法在基于 musl 的系统上构建/运行；
- 文档错误、翻译问题；

## Issue 请包含

- muslext 版本（查看 `include/muslext/muslext.h` 中的 `MUSLEXT_VERSION`）
- 目标平台和 libc 版本；
- 复现命令和最小示例；
- 完整错误日志；
- 如果涉及某个软件包，请给出名称和版本；

## 维护者如何处理

维护者会：

1. 判断问题是否属于 muslext 的适用范围；
2. 如果需要改代码，由维护者在净室条件下实现；
3. 在公开仓库更新代码、测试和文档；
4. 在 issue 中反馈结果。
